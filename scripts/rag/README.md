# RAG Scripts

This directory contains helper scripts for preparing knowledge-base documents for RAG workflows.

Run commands from the backend branch root so imports and `config.yaml` can be resolved correctly:

```bash
uv run python -m scripts.rag.clean_markdown --help
uv run python -m scripts.rag.partition --help
```

## Model Compatibility

OpenCrab's cloud knowledge base is built with:

- Embedding model: `BAAI/bge-m3`
- Rerank model: `BAAI/bge-reranker-v2-m3`

When building or querying cloud knowledge bases, configure only these two models for embedding and reranking. Using different models may produce incompatible vector spaces or inconsistent retrieval rankings.

Example `config.yaml` section:

```yaml
api:
  embed:
    type: OpenAI
    base_url: https://api.example.com/v1
    api_key: replace-me
    model: BAAI/bge-m3
    dims: 1024
  rerank:
    type: OpenAI
    base_url: https://api.example.com/v1
    api_key: replace-me
    model: BAAI/bge-reranker-v2-m3
```

The scripts use `file.rag_path` from `config.yaml` as the default workspace. The workspace is organized as:

```text
<file.rag_path>/
  raw/          # source files
  cleaned/      # cleaned Markdown/TXT
  chunks/       # JSONL chunks generated by partition.py
  checkpoints/  # ingestion checkpoints
  embeddings/   # embedding JSON files for cloud publishing
```

## 1. Clean Markdown Documents

`clean_markdown.py` normalizes Markdown/TXT files before chunking. It removes common noise such as table-of-contents lines, duplicate lines, page markers, and converts simple HTML tables to Markdown tables.

Clean all Markdown/TXT files under the default `raw/` directory:

```bash
uv run python -m scripts.rag.clean_markdown
```

Clean a specific file:

```bash
uv run python -m scripts.rag.clean_markdown \
  --input-file ./workspace/rag/raw/course.md \
  --output-dir ./workspace/rag/cleaned
```

Useful options:

- `--input-file`: clean one Markdown/TXT file.
- `--input-dir`: clean all supported files in a directory.
- `--output-dir`: write cleaned files to a custom directory.
- `--suffix`: output suffix, default `.cleaned.md`.
- `--heading-priority`: heading normalization order, default `1,2,3,4,5,6`.

## 2. Partition Documents into Chunks

`partition.py` converts cleaned documents into retrieval chunks and writes one `.chunks.jsonl` file per source document.

Partition all files under the default `cleaned/` directory:

```bash
uv run python -m scripts.rag.partition
```

Partition a specific cleaned file:

```bash
uv run python -m scripts.rag.partition \
  --input-file ./workspace/rag/cleaned/course.cleaned.md \
  --output-dir ./workspace/rag/chunks
```

Useful options:

- `--input-file`: partition one file.
- `--input-dir`: partition all supported files in a directory.
- `--output-dir`: write chunk JSONL files to a custom directory.
- `--recursive-chunk-size`: recursive chunk size, default `800`.
- `--recursive-chunk-overlap`: recursive chunk overlap, default `120`.
- `--semantic-buffer-size`: semantic splitter buffer size, default `1`.
- `--semantic-breakpoint-percentile-threshold`: semantic split threshold, default `95`.

## 3. Programmatic Upload Pipeline

`pipeline.py` is a library module used by backend APIs. It is not a standalone CLI script.

The pipeline performs these steps for uploaded Markdown/TXT files:

1. Persist the upload to `raw/`.
2. Clean the file into `cleaned/`.
3. Build chunks with embeddings.
4. Restore embedding items into the configured vector store/database.
5. Remove temporary intermediate files.

Use `run_rag_pipeline_for_file(...)` from backend code when integrating this flow into an API or task.

## 4. Serve Cloud Knowledge-Base Files

The cloud RAG file server lives at `scripts/serve_rag_cloud.py`. It serves a generated `manifest.json` and JSON files from a local directory.

Serve embedding JSON files from the default `./rag` directory:

```bash
uv run python scripts/serve_rag_cloud.py
```

Serve a specific directory:

```bash
uv run python scripts/serve_rag_cloud.py \
  --rag-dir ./workspace/rag/embeddings \
  --host 0.0.0.0 \
  --port 8001 \
  --knowledge-base-id opencrab-course \
  --version dev
```

Endpoints:

- `GET /manifest.json`: lists available JSON files and metadata.
- `GET /files/{filename}`: downloads one JSON file from `--rag-dir`.

The backend `rag_cloud` configuration can point to this server during local testing:

```yaml
rag_cloud:
  base_url: http://127.0.0.1:8001
  manifest_path: /manifest.json
  timeout_ms: 30000
  api_key: ""
```
